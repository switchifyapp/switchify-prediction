# v0.3.0

Prediction of the next two words from both engines. The model, the tokenizer,
the SQLite formats and the single-word APIs are unchanged, so existing personal
databases keep working. **Worker protocol 3 and the bundle manifest change,** so
applications must update their pinned manifest and workers together.

## Two-word phrases (#33)

- **Statistical.** `Predictor::predict_phrases(before, prefix, options)` returns
  phrases of exactly two words. The first word follows the `predict` rules. The
  second is a word seen after it in the baseline or the usable learned counts.
  Phrases rank by the joint probability of both words. The CLI's `predict`
  command takes `--phrases`.
- **Generated.** `Refiner::generate_phrases(before, prefix, session, exclude,
  limit)` returns up to three phrases through `poll`, in the new
  `Refined::phrases` field. It has the same input limits, latest-only queue and
  2-second reply deadline as `generate`. The worker searches both words in one
  beam search within the existing budget of 64 forward evaluations and a
  1,600 ms cutoff. Early stopping still never changes the result. The stream CLI
  accepts `generate_phrases`.
- **Results.** In CI, with three statistical and three generated phrases on
  1,000 frozen queries, both words were right for 25.3% of queries on macOS ARM
  and 25.2% on Windows x64. Generated phrases alone reached 19.9% and 19.8%;
  statistical phrases alone 5.4%. Generation took a median of 208 ms on macOS
  and 1,329 ms on the slower Windows runner, close to single-word generation on
  the same runs (170 ms and 1,270 ms). There were no failures. See
  `docs/two-word-phrases.md`.
- **Measuring phrases.** `scripts/generation_evaluate.py` gains `--phrases`, and
  CI runs it on Windows and macOS.

## Compatibility

- **Worker protocol 3.** Parents reject protocol 2 workers, and protocol 3
  workers are needed for phrases. Word ranking and generation are unchanged.
- **Bundle manifest.** The policy records protocol version 3 and the phrase
  search, and packaged builds report `worker_protocol` 3. The compiled manifest
  must equal the bundle's `model-bundle.json`, so existing bundles need the new
  manifest. The model and tokenizer files and their hashes are unchanged.
- **API.** `Refined` gains a public `phrases` field, so code that constructs
  `Refined` must set it. Code that only reads it is unaffected.

These are regression measurements on frozen fixtures whose overlap with model
pretraining is unknown, not evidence of real users' accuracy. Prepared CI
bundles are unsigned; platform applications sign their embedded workers through
their own packaging workflows. Publishing this release, and updating Switchify
PC's worker assets and library pin to it, need separate approval.
