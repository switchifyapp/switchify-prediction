# v0.5.0

Neural inference uses less memory and responds faster. The statistical baseline,
pinned neural model, worker protocol 3, personal database schema, scoring policy
and public APIs are unchanged.

## Neural memory and inference

- Share packed quantized embeddings with the tied output layer and decode only
  requested rows, removing roughly 108 MiB of dense embedding storage. Release
  the temporary source GGUF buffer after loading.
- Batch candidate reranking, retain a bounded 64-entry score cache for the
  prepared context, and reuse generation probability normalizers.
- Bound both Candle and Rayon thread pools using the configured thread count.
- Use baseline SSE2 for portable x86-64 CPU Q8_0/F32 matrix products. Other
  architectures, AVX2-target builds, accelerated builds and precision overrides
  retain Candle's implementation. No new CPU instruction requirement is added.

## Measured results

On the Windows Ryzen AI 9 HX 370 reference machine, with the same portable
four-thread worker configuration, the SSE2 iteration reduces controller-inclusive
frozen reranking median from 540.4 to 152.5 ms and p95 from 813.4 to 227.5 ms.
All 1,760 predictions and quality cells match, with zero failures. This comparison
starts after the earlier memory and reranking changes, rather than at v0.4.0.

A sequential fresh-context benchmark with one thread, fixed CPU affinity and a
50% one-CPU quota reduces long-context median from 2,018.9 to 523.1 ms. Replies
over two seconds fall from 21/36 to 0/36. These are single-machine measurements,
not a minimum hardware specification. Memory is essentially unchanged by SSE2
itself; the dense embedding saving comes from the earlier memory change.

The 100-query generation spot check falls from 1,038.7 to 272.3 ms median,
with unchanged hit totals. Faster inference produces five more words before the
existing timed search cutoff, so generation output is not claimed identical.
See [the portable SSE2 report](../neural-portable-sse2.md) and
[the earlier hill climb](../neural-hill-climb.md) for raw evidence and limitations.

The 150 ms p95 refinement target still fails on the portable evaluation. Existing
quality failures remain in development/documents/1 and development/messages/0.
This release does not promote neural generation to a qualified production model.
Low-end physical hardware and GPU research was closed as not planned in #39/#43.

## Benchmarking and distribution

Fresh-only workloads distinguish inference from repeated score-cache lookups.
Windows Job Object CPU quotas are applied before the worker starts; reports
record affinity, per-request CPU time, script hashes and UTC run boundaries.
Windows CPU accounting can have 15.625 ms resolution. Model and workload hashes
make paired comparisons checkable.

Neural audit documentation adds the narrow RUSTSEC-2026-0429 exception for the
pinned Candle/zip dependency. Candle never extracts untrusted archives and the
worker loads the hash-pinned GGUF. See neural/SECURITY.md for all exceptions.

Model weights are not redistributed. CLI and companion bundles remain unsigned;
applications sign embedded workers in their own release process. No Switchify PC
or Android release, dependency upgrade, model change or API migration is included.
