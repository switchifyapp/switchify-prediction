# v0.4.0

The statistical baseline can be read from a compact n-gram file, and the model
bundle ships that file as `english.ngrams` beside `english.sqlite`. The model,
the tokenizer, the SQLite formats, personal learning, the neural companion,
worker protocol 3 and the bundle manifest are unchanged. Both formats give
bit-identical predictions, and the v0.3.0 CLI gave byte-identical output on a
cross-check of word and phrase queries.

## The n-gram baseline file (#40)

- **Format.** `english.ngrams` holds the same vocabulary, counts and provenance
  as `english.sqlite` as sorted arrays with a whole-file SHA-256 trailer. The
  predictor indexes the file's bytes in memory instead of loading rows into
  maps. There is no new dependency and no `unsafe` code. See
  `docs/baseline-format.md`.
- **One prediction path.** `Predictor::open` accepts either file. A SQLite
  baseline is validated exactly as before and then encoded in memory, so both
  formats take the same prediction code.
- **CLI and API.** `convert --input english.sqlite --output english.ngrams`
  copies a SQLite baseline into the file and fails, leaving no file, unless the
  logical fingerprint matches. `build --format ngrams` builds a custom model as
  a file directly; the production build stays SQLite and is converted. `validate`, including `--production`, accepts both formats
  and reports `format`. The Rust entry points are `build`, `build_ngrams`,
  `convert` and `validate`; `production::validate_english` accepts both
  formats, and the new `ngrams` module exposes the file reader (`Ngrams::open`
  and `Ngrams::parse`) and its `Metadata`.
- **Results.** Production model, release build, Windows 11 on a Ryzen AI 9
  HX 370: the file is 8.5 MB instead of 29.8 MB, `Predictor::open` takes 20 ms
  instead of 2,844 ms, and the CLI `predict` process peaks at 14 MiB instead of
  134 MiB. The production SQLite model and its conversion gave identical words
  and scores on 81,118 held-out word and phrase queries, with and without
  learning, and the v0.3.0 CLI and this one gave byte-identical JSON on 40
  word and phrase queries. Malformed and truncated files are rejected. macOS and low-end
  hardware were not measured (#39).

## The model bundle (#45)

- `switchify-english-en-aac-oanc-v1.zip` gains `model/english.ngrams`
  (SHA-256 `c6df388c845354a059333b1e4abe68719e5a7016e8514c44581e14ed16bf964a`)
  and `model/ngrams-validation.json`. The build converts the validated
  `english.sqlite`, validates the file as the production model, and refuses to
  package it unless its hash is the pinned one. `quality-report.json` records
  `ngrams_sha256`.
- `english.sqlite` stays in the bundle for applications that still pin it.
  Removing it and making the file the default `build` output are later work.
- The packaged smoke test validates both files, checks they share a logical
  fingerprint and give identical predictions, then learns, predicts and resets
  against each.

## Compatibility

- **Applications** can switch their pinned baseline from `english.sqlite` to
  `english.ngrams` by changing only the path they open; the personal database and its schema
  are untouched. Applications that keep `english.sqlite` need no change.
- **`validate` output** gains a `format` field, `"sqlite"` or `"ngrams"`.
  Everything else in the record is unchanged for SQLite.
- **API.** `Validation` gains a public `format` field, so code that constructs
  `Validation` must set it. Code that only reads it is unaffected.
  `Predictor::model_payload_bytes` now reports the baseline's bytes in memory
  plus the learned counts, so evaluation reports show a different value for
  the same model.
- **Neural companion.** Worker protocol stays 3 and the workers, model bundle
  manifest and deadlines are unchanged, so v0.3.0 worker assets keep working
  with this library.

These are measurements on one development machine and regression checks on
frozen fixtures, not evidence of real users' accuracy or of switch savings.
Prepared CI bundles are unsigned; platform applications sign their embedded
workers through their own packaging workflows. Updating Switchify PC to the
n-gram file is switchifyapp/switchify-pc#1090.
